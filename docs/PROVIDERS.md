## Evidence and limits

The current BimpeAI Custom API guide says integrations can be configured through its SDK/API, but channels such as telephony/voice are connected on the dashboard Deploy screen; the API can list channel connections but cannot create or remove them. The saved Custom API action's dynamic request template has been exercised through the agent in Playground, including required fields, a supplied meter, a supplied account and phone, and omitted optional fields. The deployment guide says inbound telephony uses BimpeAI's Telephony card, a number linked under Team settings, and a voice profile configured under Settings → Voice. The public hackathon materials explicitly place Temlio numbers inside BimpeAI through a SIP trunk. In the authenticated account, the agent has no assigned number or channel. The BYO SIP form needs an already owned E.164 number, SIP host/port, username, password, and provider-side inbound forwarding; none is visible for the hackathon allocation. Imported numbers have no Bimpe monthly number fee, but usage can be charged. The ordinary Nigerian local number purchase option quotes ₦4,000 per month, and the owner requires separate approval before any paid resource is purchased.

A 4 October Playground test exposed a difference between server idempotency and agent behavior: requesting a manual retry of already successful ticket `LL-0024` made the agent send a new key and create duplicate `LL-0040`. A controlled lost-response test persisted `LL-0041` before BimpeAI timed out; a later request for a fresh ticket for the same issue sent a new key and created duplicate `LL-0042`. The two latter rows had one identical canonical payload hash. The shared workflow now contains explicit retry and transfer-claim rules; one uncertain-error follow-up refused submission, but these model-steered rules do not prove duplicate safety. BimpeAI's SDK documentation for idempotent calls to its own Console API is not evidence for outbound Custom API tool retry behavior. See [BIMPEAI_SETUP.md](BIMPEAI_SETUP.md).

The `LAGOSHACKNIGHT` offer code was already applied to Yusuf's account on 2 October 2026, granting a 30-day Starter trial and ₦5,000 wallet credit. The existing billing screen shows a ₦40,000/month Starter plan with a November 1 renewal date; no plan, number, or payment settings were changed during LightLine setup. The credit does not by itself provision a Temlio number.

The authenticated Bimpe voice selector directly lists Mary, Osagie, Remi, and Umar as YarnGPT voice options. Mary was saved for the LightLine agent. YarnGPT's standalone API docs describe a separate TTS API, but LightLine does not need a direct API integration for the selected Bimpe voice.

## Workflow assignment recovery

Before a dedicated agent was created, saving the new `LightLine Complaint Intake` workflow affected the selected existing `Yusuf Saheed's Agent`. Bimpe's saved-workflow toast said edits apply to all agents using it; after the LightLine agent was created the workflow showed two agents using it. Workflow ID from the dashboard URL: `cmus5pyvr02sipy87kqncsgbu`. The original Yusuf agent had no voice profile and there were no other existing account agents/workflows. The dashboard's Settings → Agent page has no workflow control; Playground's “Change workflow” opens the workflow catalogue, and no unassign option was visible. Current official docs say `workflow_id` is an agent update field but do not document whether `null` detaches it. Later LightLine retry and transfer rules were saved to this shared workflow, so they also apply to the existing agent. No unsupported API request or deletion was attempted. The assignment remains a known side effect requiring provider/owner correction. The LightLine agent is separately present in Development and has Mary YarnGPT selected. No credentials or browser storage were inspected.
